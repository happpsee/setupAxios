## 1. 角色 & 背景

### 1.1 项目背景

AIServer 是一个AI智能客服项目，用于回复用户关于店铺的相关信息。当前系统需要客服人员手动回复每条消息，在高峰期响应速度跟不上，且重复性问题（如价格咨询、营业时间等）占用大量人力。需要增加自动回复功能，让AI自动处理常见问题，降低人工客服负担。

### 1.2 目标用户

- 店铺客服人员：希望通过自动回复减少重复劳动
- 店铺顾客：希望快速获得常见问题的答案
- 店铺管理者：希望降低客服人力成本

### 1.3 使用场景

- 顾客咨询商品价格时，系统自动匹配SKU返回价格
- 顾客询问营业时间/地址时，自动回复预设信息
- 顾客发送常见问题时（退换货政策、配送范围等），AI匹配知识库自动回复

---

## 2. 任务

### 2.1 核心功能

1. 关键词匹配自动回复：根据用户消息中的关键词匹配预设回复模板
2. 价格查询：识别商品名称，自动从商品库查询价格并回复
3. 人工转接：当AI无法处理时，自动转接人工客服
4. 回复记录：所有自动回复记录到对话历史中

### 2.2 用户故事

- 作为 店铺顾客，我想要 发送"XX商品多少钱"后立即收到价格回复，以便 快速做购买决策
- 作为 客服人员，我想要 常见问题由AI自动处理，以便 专注于高价值对话
- 作为 店铺管理者，我想要 查看自动回复的成功率和转人工率，以便 评估AI客服效果

### 2.3 功能优先级

| 优先级       | 功能               | 说明                       |
| ------------ | ------------------ | -------------------------- |
| P0（必须有） | 关键词匹配自动回复 | 解决最常见问题的自动应答   |
| P0（必须有） | 人工转接           | AI兜底机制，保证用户体验   |
| P1（应该有） | 价格查询           | 高频场景，但依赖商品库接口 |
| P2（可以有） | 回复数据统计       | 后续迭代，用于效果评估     |

## 3. 约束

### 3.1 技术约束

- 基于现有 AIServer 架构：TypeScript + Express + Langchain
- 关键词匹配延迟 < 500ms
- 商品价格查询依赖现有商品库API
- 回复内容需支持与 chroma 向量库中的知识库内容做语义匹配

### 3.2 业务约束

- 自动回复内容必须经过运营审核后才能上线
- 涉及价格的信息必须确保准确，不确定时必须转人工
- 敏感词和负面情绪消息必须自动转人工

### 3.3 设计约束

- 项目为AI客服系统，回复风格应专业、友好、简洁
- 色调参考项目已有设计规范（如有定义则保持一致）

## 4. 验收期望

### 4.1 功能验收标准

- [ ] 发送包含"价格"关键词的消息，系统返回对应商品价格
- [ ] 发送"营业时间"，系统返回预设的营业时间信息
- [ ] 发送AI无法识别的问题，自动转接到人工客服
- [ ] 所有自动回复出现在对话记录中，标注为"AI自动回复"

### 4.2 非功能验收标准

- [ ] 关键词匹配响应时间 < 500ms
- [ ] 自动回复准确率 > 90%（对于预设关键词场景）
- [ ] 人工转接的平均等待时间不高于现有水平

### 4.3 边界情况

- 用户消息同时匹配多个关键词时，按优先级选择回复模板
- 商品库查询失败时，转人工并提示"正在为您转接人工客服"
- 用户连续发送多条消息，每条独立匹配和回复
- 包含敏感词的消息不自动回复，直接转人工
