# PRD 文档模板

使用此模板时，所有 **一级章节（## 1-5）不可删除**，二级章节可根据项目实际情况调整。

---

# [产品/功能名称]

## 文档元信息

- **文档版本**: v1.0
- **日期**: YYYY-MM-DD
- **状态**: 待开发
- **作者**: [填写作者(来自于package.json中的author字段)]

---

## 1. 角色 & 背景

### 1.1 项目背景

> 描述为什么做这个需求，解决什么业务问题或用户痛点

### 1.2 目标用户

> 描述目标用户画像：谁在使用？有什么特征？

### 1.3 使用场景

> 描述核心使用场景：用户在什么情况下使用这个功能？

---

## 2. 任务

### 2.1 核心功能

> 列出所有核心功能点，每个功能用一两句话描述

1. [功能1]
2. [功能2]
3. [功能3]

### 2.2 用户故事

> 用"作为...我想要...以便..."的格式描述关键用户故事

- 作为 [角色]，我想要 [功能]，以便 [价值]
- 作为 [角色]，我想要 [功能]，以便 [价值]

### 2.3 功能优先级

| 优先级       | 功能 | 说明 |
| ------------ | ---- | ---- |
| P0（必须有） |      |      |
| P1（应该有） |      |      |
| P2（可以有） |      |      |

---

## 3. 约束

### 3.1 技术约束

> 技术栈限制、系统依赖、接口要求等

### 3.2 业务约束

> 业务规则、合规要求、时间节点等

### 3.3 设计约束

> 色调、风格、品牌规范等（参考项目 CLAUDE.md 和已有设计规范）

---

## 4. 验收期望

### 4.1 功能验收标准

> 每个功能点对应的可验证的完成标准

- [ ] [功能1] 的验收标准
- [ ] [功能2] 的验收标准

### 4.2 非功能验收标准

> 性能、可维护性、安全性等非功能要求

- [ ] 页面加载时间 < 2秒
- [ ] 核心流程测试覆盖

### 4.3 边界情况

> 异常情况、边界输入、降级策略
