### 1.1 项目背景

SetupAxios 已发布到 npm（`setup-axios@1.0.0`），核心功能（裸请求、局部拦截器、装饰器工具系统）和打包流程均已就绪。但 npm 包页面目前没有 README，用户在 [npmjs.com](https://www.npmjs.com/package/setup-axios) 上看到一个空白的包页面，无法了解这是什么库、怎么用、和 Axios 有什么区别。

README 是开源项目的"门面"——用户在决定用不用之前，第一眼看到的就是 README。一个清晰、示例到位、差异化突出的 README 直接影响安装转化率。

## 3. 约束

### 3.1 技术约束

- 格式：Markdown
- 语言：纯中文
- 长度：精简实用，控制在 ~150 行
- 代码示例：TypeScript 语法，可直接复制运行
- 文件位置：项目根目录 `README.md`
- npm 的 `files` 字段已含 `dist/`，README 不在内不影响发布，但 npm 会自动将根目录的 README 关联到包页面

### 3.2 风格约束

- **多用 emoji** 图标作为视觉锚点（标题左侧、段落前缀），让文档更有亲和力
- 代码示例优先展示差异化能力（`isTempory: true` 局部拦截器、`.use()` 链式调用）
- 不罗列完整参数表，精简展示核心用法
- 保持 Axios 用户熟悉的命名和 API 风格，降低迁移心理成本

### 3.3 设计约束

- 标题层级不超过 3 级（`#` / `##` / `###`）
- 代码块必须标注语言类型（` ```ts `）
- Badges 放在标题下方第一行，作为视觉锚点
- 每个章节用对应 emoji 开头，形成固定的视觉节奏

### 4.3 边界情况

- GitHub 和 npmjs.com 对 Markdown 渲染有差异（如 HTML 标签支持范围），代码块统一使用缩进 + 语言标注确保兼容
- Badges 图片依赖 shields.io 服务，若该服务不可用则显示 alt 文本——这是可接受的降级
- 中文在终端等纯文本环境中可能出现对齐问题——由用户终端自行处理，不考虑
